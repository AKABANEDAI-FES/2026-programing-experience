# 塗り潰し機能の実装方針

## 決定

画面②のお絵かき実装は、SVG のポリライン方式から HTML `<canvas>` を使うラスター方式へ移行する。描画領域は、白背景と塗り絵の下絵を持つ**背景 Canvas**と、ユーザーの操作だけを保持する透明な**編集 Canvas**の二層構成にする。作品の保存・放流形式は PNG の Data URL（`data:image/png;base64,...`）とする。

この方針は本ブランチで試作・レビューし、フロントエンド要件定義書と API 仕様書にも正式に反映する。

## 採用理由

- バケツ塗りは画素の連結領域を扱うため、SVG の線だけで実装するより Canvas の `ImageData` を使うほうが単純で堅牢になる。
- 消しゴム・色・線幅を、子どもに馴染みのあるペイント操作として一貫して提供できる。
- API がすでに `image_base64` の PNG Data URL を受け取る契約であり、保存形式と一致する。
- 本体の描画領域を固定解像度で管理すれば、大画面表示用の画像をそのまま出力できる。

## 実装設計

### 描画面

- 出力解像度は現行 SVG と同じ **1000 x 600 px** とし、CSS による表示サイズとは切り離す。
- 背景 Canvas には白背景を描画し、塗り絵モードでは下絵 SVG を `Image` として読み込んで重ねる。編集 Canvas は透明のままにし、両 Canvas を CSS Grid の同じ領域に重ねる。
- Pointer Events は編集 Canvas だけで受け付ける。モード切替時には背景 Canvas の白背景と下絵だけを描き直し、編集 Canvas の描画内容とUndo履歴は両モードで共有して保持する。
- Pointer Events を用い、表示上の座標を 1000 x 600 の内部座標へ変換する。マウスの左ボタン、タッチ、ペンを対象にする。
- 操作ツールは、ペン、消しゴム、バケツ塗り、色選択、線幅選択、Undo、全消去を用意する。消しゴムは編集 Canvas のみを消去するため、塗り絵の下絵を壊さない。全消去は誤操作を防ぐため確認ダイアログを出し、消去前の状態へUndoできるようにする。
- 「次へ」では、一時的な合成 Canvas に背景、編集の順で描画してから `toDataURL('image/png')` を実行し、`imageData` として App の状態に保存する。二層を直接 `toDataURL` することはできない。

### バケツ塗り

- 背景と編集レイヤーを合成した `ImageData` を参照し、クリック地点の目標色と近い連結領域だけを置換する。塗り結果は編集 Canvas にだけ書き込むため、下絵の線は背景レイヤーとして残る。
- 実装は再帰ではなく、キューを用いる反復型の scanline flood fill とする。大きな領域でもコールスタックを使い切らない。
- 色判定には RGB の許容差を設け、アンチエイリアスされた下絵の境界をまたがない値を実機で調整する。
- 探索した連結領域が Canvas の四辺のいずれかへ到達した場合は背景とみなし、塗り結果を編集 Canvas へ反映しない。閉じた領域だけを塗り潰しの対象にする。
- Canvas がペンの縁に生成する半透明のアンチエイリアス画素は、塗り領域に隣接する画素だけを対象に、既存の線の背後へ塗り色を合成する。色許容差を過度に広げず、線と塗り面の間に白い隙間が残ることを防ぐ。
- 置換先が目標色と十分近い場合は何もしない。塗りは不透明な色、消しゴムは透明で編集 Canvas を更新する。

### Undo

- 編集 Canvas の操作前の `ImageData` をスナップショットとして保持し、直近の操作を取り消せるようにする。
- スナップショットは最大10件とし、背景 Canvas は履歴に含めない。モード切替では履歴を維持し、全消去も消去前のスナップショットを保存してUndo可能にする。

### 画像と API

- モードにかかわらず、送信する画像は `image/png` の Data URL に統一する。
- API 側では Data URL の MIME 種別、Base64 形式、サイズ上限、`mode`、コマンド数・コマンド形式を検証する。
- 保存先の R2 には PNG バイナリを保存し、作品メタデータにはモード・コマンド・作成日時・画像キーを保持する。大画面通知は画像 URL/キーを参照する。

## 段階的な実装順

1. **完了:** 画面②を二層 Canvas 化し、自由描画、塗り絵下絵、編集内容を維持するモード切替を実装する。
2. **完了:** ペン、色、線幅、消しゴム、Undo、全消去を追加する。
3. **完了:** flood fill を追加し、下絵・描画済み領域・境界での動作を調整する。
4. 合成 PNG を `imageData` として出力し、「次へ」の画面遷移から画面③以降の放流フローへ接続する。
5. バックエンドの検証・R2 保存・大画面通知を実装する。

## 受け入れ条件

- 自由描画と塗り絵の両方で、マウスドラッグによる描画と消しゴムが使える。
- 塗り絵の閉じた領域を塗りつぶせ、輪郭線を越えて隣接領域を塗らない。
- 背景と編集レイヤーを合成した描画結果が、1000 x 600 px の PNG Data URL として取得できる。
- 塗り絵の下絵を含む完成画像が、画面遷移後・放流後も同一の見た目で表示できる。
- 操作後の UI がキオスク用の画面サイズでも崩れず、タッチ操作時にページがスクロールしない。

## 主なリスクと確認事項

- PNG Data URL は SVG より大きくなりやすいため、送信サイズの上限を先に決める。目安は、実際の 1000 x 600 px 作品で計測して決定する。
- 下絵の黒線がアンチエイリアスされるため、塗りつぶしの色許容差は画像に合わせた調整が必要になる。
- Canvas のビットマップは SVG のように線単位で後編集できないため、最大10件の `ImageData` スナップショットでUndoを提供する。
- `image_base64` の API 仕様例にある `commands` の文字列配列は、共有型のオブジェクト配列と不一致である。Canvas 化とは別に、共有型を正として API 仕様書を修正する。
