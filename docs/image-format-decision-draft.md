# 【仮】作品画像形式の検討メモ

> **この文書は正式な技術仕様ではありません。**
>
> 塗り潰し機能を含むお絵かき画面の実装方針を決めるための、仮の検討メモです。最終決定後は、要件定義書とAPI仕様書へ内容を反映します。

## 現時点の結論（仮）

参加者が作成する作品は、`<canvas>` で描画し、**PNG形式のData URL**として保存・送信する方針を推奨します。

## SVGとPNGの比較

| 観点            | SVG                                          | PNG（Canvas）                                     |
| :-------------- | :------------------------------------------- | :------------------------------------------------ |
| 自由な線画      | 線を図形として保持できる                     | 一般的なペイントと同じように描画できる            |
| 塗り潰し        | 閉じた領域の判定が必要で実装が複雑           | 画素単位のバケツ塗りを実装しやすい                |
| 消しゴム        | 線単位の削除に向く                           | 消しゴムでなぞって消す操作に向く                  |
| 線ごとの後編集  | 色・太さ・位置の変更や、特定の線の削除が可能 | 描画結果は1枚の画像となり、特定の線だけを選べない |
| 拡大表示        | 劣化しない                                   | 大きく拡大すると粗くなる場合がある                |
| 現行APIとの整合 | API仕様の画像形式を変更する必要がある        | `image_base64` のPNG形式と一致する                |

## 「線ごとの後編集」とは

SVGでは、描いた線がそれぞれ独立したPathやPolylineとして残ります。そのため、描画後に「青い線だけを消す」「赤い線だけを太くする」「特定の線を移動する」といった操作ができます。

PNGでは、描画結果は色の付いた画素の集合として保存されます。どの画素がどの線に由来するかは保持されないため、特定の線だけを選択して編集することは基本的にできません。消しゴムでなぞる、または全消去して描き直す操作になります。

## 今回PNGを推奨する理由

- 来場者の体験は「描く → 塗る → 動きを付ける → 放流する」という一方向の流れであり、描画後に線単位で編集する要件がない。
- 子どもにも分かりやすいバケツ塗りを実装しやすい。
- 消しゴムや色選択を一般的なペイント操作として提供できる。
- 現在の放流API仕様が `data:image/png;base64,...` を受け取る形式であり、そのまま整合する。

## 想定する構成（仮）

- 塗り絵の下絵は背景レイヤーとして表示する。
- 来場者のペン・消しゴム・塗り潰しは編集レイヤーで扱う。
- 「次へ」押下時に編集結果をPNGのData URLへ変換する。
- 放流APIへ `image_base64` としてPNG Data URLを送信する。

## 最終決定前の確認事項

- 塗り潰し機能を必須要件として確定するか。
- 作品画像の解像度・最大データ量をどの程度にするか。
- Cloudflare R2へ保存した画像を大画面へ配信する方法をどうするか。
- PNG採用後、既存のお絵かき画面のSVG実装をCanvas実装へ置き換えるか。
